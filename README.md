# Mini Trade — мини ERP для торговли (TJS)

Офлайн-программа для Windows: продажи, закуп, склад, финансы, отчёты.
C# · WPF · .NET 10 · SQLite · Entity Framework Core · MVVM (CommunityToolkit.Mvvm).
Лицензирование — отдельный сервер ASP.NET Core + PostgreSQL с веб-панелью администратора.

## Состав решения

```
MiniTrade.slnx
├─ src/MiniTrade.Core              Домен, EF Core (SQLite), бизнес-сервисы — без зависимостей от UI
├─ src/MiniTrade.Licensing.Shared  Модель лицензии, DTO API, подпись/проверка токена (ECDSA P-256)
├─ src/MiniTrade.Desktop           WPF-клиент (MVVM): окна активации, входа, главное окно с 8 модулями
├─ src/MiniTrade.LicenseServer     HTTPS API лицензирования + веб-панель администратора (Razor Pages)
├─ tests/MiniTrade.Tests           xUnit: учёт денег/остатков, криптография лицензий, API сервера
├─ deploy/postgres-schema.sql      Схема центральной базы лицензий для PostgreSQL
└─ tools/sync-public-key.*         Перенос публичного ключа сервера в клиент
```

## Архитектура

```
 ┌──────────── Windows-ПК (офлайн) ────────────┐          ┌──────── Сервер ─────────┐
 │ WPF Views ──binding── ViewModels             │  HTTPS   │ /api/v1/license/*        │
 │                         │                    │ ───────► │ LicenseService           │
 │                  Core services               │          │  (подписывает токены     │
 │      (Sales, Purchase, Warehouse, Finance,   │ ◄─────── │   приватным ключом)      │
 │       Reports, Catalog, Settings)            │  токен   │ Панель /admin            │
 │                         │                    │          │        │                 │
 │      SQLite: %LocalAppData%\MiniTrade\       │          │   PostgreSQL             │
 │      minitrade.db (своя у каждой установки)  │          │   (клиенты, ключи,       │
 │ license.json — подписанный токен лицензии    │          │    устройства, журнал)   │
 └──────────────────────────────────────────────┘          └──────────────────────────┘
```

* **Торговые данные полностью локальны.** Сервер хранит только сведения о лицензиях; работа программы не зависит от него после активации.
* **MVVM:** View (XAML) ↔ ViewModel (`ObservableObject`, `RelayCommand`) ↔ сервисы Core. Навигация — через `DataTemplate` ViewModel→View, зависимости — через DI (`Microsoft.Extensions.DependencyInjection`).
* **Расширяемость:** новый модуль = сервис в Core + ViewModel + View + пункт меню в `MainViewModel`. Схема БД меняется через миграции EF Core (`src/MiniTrade.Core/Data/Migrations`), которые применяются автоматически при запуске.

## Модули программы

| Модуль | Что умеет |
|---|---|
| Главная | Выручка сегодня/за месяц, чистая прибыль, деньги в кассах, стоимость склада, долг поставщикам, график 7 дней, заканчивающиеся товары, последние продажи |
| Финансы | Кассы и остатки, приход/расход по статьям, перемещение между кассами, журнал операций за период |
| Продажи | Чек со сканированием штрихкода/артикула, история, возврат по позициям (частичный), журнал возвратов |
| Закуп | Приход от поставщика с полной/частичной оплатой, история, погашение долга, долги по поставщикам |
| Склад | Остатки с поиском и подсветкой минимумов, перемещения между складами, инвентаризация, журнал движения |
| Справочники | Товары, категории, клиенты, поставщики, склады, кассы (используемые записи архивируются, а не удаляются) |
| Отчёты | Продажи в разрезах (товары, категории, покупатели, дни, склады) с маржой, долей и ABC-анализом; закупки по поставщикам; прибыль (P&L, средний чек, рентабельность); движение денег по кассам и статьям; остатки с фильтром «ниже минимума»; фильтр по складу, поиск, экспорт в CSV с итогами |
| Настройки | Реквизиты компании, пользователи и роли, лицензия (онлайн-проверка, смена ключа), резервная копия БД |

## Правила учёта

* Валюта — **TJS (сомони)**, суммы `decimal`, округление до дирама (2 знака, `MidpointRounding.AwayFromZero`); количества — 3 знака.
* Себестоимость — **FIFO** (по партиям) или **средневзвешенная** (выбор в настройках); в строке продажи фиксируется себестоимость на момент продажи, возврат приходует товар по ней же. Партии всегда равны положительному остатку (приход после продажи в минус сначала покрывает минус).
* Взаиморасчёты с контрагентами считаются **из одного регистра** (справочник, выписка, баланс на дату, главная, долги по поставщикам): закупки, возвраты поставщику, продажи в долг, возвраты покупателей, платежи и начисления.
* Возврат по продаже в долг сначала **уменьшает долг покупателя**, из кассы выдаётся только сумма сверх долга.
* Каждый документ проводится **одной транзакцией**: документ + движение товара + кассовая операция. Ошибка (нехватка товара или денег) откатывает всё.
* Продажа в минус запрещена (можно разрешить в настройках компании). Расход из кассы больше остатка запрещён.
* Остатки ведутся в регистре `StockBalances`, каждое изменение пишется в журнал `StockMovements`; кассы — `CashRegisters.Balance` + журнал `CashTransactions`. Тесты проверяют, что регистры совпадают с журналами.
* Прибыль = (продажи − возвраты) − себестоимость − операционные расходы (ручные расходы, кроме «Изъятие наличных») − списания товара − недостачи инвентаризации + излишки инвентаризации.
* Тесты проверяют балансовое тождество: деньги + склад по себестоимости + взаиморасчёты = накопленный результат.

## Лицензирование

1. При первом запуске — окно регистрации: **пробный период 14 дней** (ФИО, компания, телефон) или **активация ключом** `MT-XXXXX-XXXXX-XXXXX-XXXXX`.
2. Клиент генерирует **ID установки** (GUID, `%LocalAppData%\MiniTrade\installation.id`) и **отпечаток устройства** (SHA-256 от MachineGuid Windows).
3. Сервер выдаёт **токен**, подписанный ECDSA P-256. Приватный ключ есть **только на сервере**, в клиент вшит лишь публичный ключ.
4. Токен привязан к установке и устройству, содержит тип (пробная / годовая / бессрочная), срок и `CheckBefore` (+30 дней).
5. Клиент работает **офлайн**, проверяя подпись, устройство, срок и откат системных часов. При запуске выполняется быстрая онлайн-проверка (4 с); если сервер недоступен — работа продолжается. Без связи с сервером лицензия действует до 30 дней.
6. Администратор может **заблокировать, продлить, сменить тип/срок/число устройств, отвязать устройство** — изменения применяются при следующей онлайн-проверке.
7. Один ключ — одно устройство по умолчанию; пробный период выдаётся оборудованию один раз (переустановка продолжает тот же триал).
8. API защищён ограничением частоты запросов (по IP), HTTPS-редиректом и HSTS.

### API

| Метод | Назначение |
|---|---|
| `POST /api/v1/license/register` | Регистрация клиента и выдача пробной лицензии |
| `POST /api/v1/license/activate` | Активация ключа на устройстве |
| `POST /api/v1/license/validate` | Проверка и обновление токена |
| `GET /api/v1/health` | Проверка доступности |

## Запуск для разработки

Требуется .NET 10 SDK.

```bash
dotnet build MiniTrade.slnx
```

```bash
dotnet test tests/MiniTrade.Tests
```

**Сервер лицензий** (Development: SQLite, логин панели `admin` / `admin123`):

```bash
dotnet run --project src/MiniTrade.LicenseServer --launch-profile https
```

Панель: https://localhost:7155/admin. Для доверия к dev-сертификату на Windows выполните `dotnet dev-certs https --trust`.

При первом запуске сервер создаёт ключ подписи `src/MiniTrade.LicenseServer/keys/license-signing.pem` (не коммитится). **Перенесите публичный ключ в клиент и пересоберите его:**

```powershell
./tools/sync-public-key.ps1
```

**Клиент** (только Windows):

```bash
dotnet run --project src/MiniTrade.Desktop
```

Адрес сервера лицензий задаётся в `appsettings.json` рядом с `MiniTrade.exe` (`LicenseServerUrl`). Там же можно указать свой путь к базе (`DatabasePath`). Вход по умолчанию: `admin` / `admin` — смените пароль в «Настройки → Пользователи».

## Развёртывание

**Клиент:**

```bash
dotnet publish src/MiniTrade.Desktop -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o publish/client
```

**Сервер** (Linux/Windows):

```bash
dotnet publish src/MiniTrade.LicenseServer -c Release -o publish/server
```

Настройки сервера (`appsettings.json` или переменные окружения, например `ConnectionStrings__LicenseDb`):

| Ключ | Описание |
|---|---|
| `Database:Provider` | `PostgreSQL` (по умолчанию) или `Sqlite` |
| `ConnectionStrings:LicenseDb` | Строка подключения к PostgreSQL |
| `Licensing:PrivateKeyPath` | Путь к приватному ключу (создаётся автоматически; храните резервную копию в надёжном месте) |
| `Licensing:PrivateKeyPem` | Альтернатива: ключ из секрета/переменной окружения |
| `Admin:Username`, `Admin:PasswordHash` | Учётная запись панели; хеш: `dotnet MiniTrade.LicenseServer.dll --hash-password "пароль"` |
| `Licensing:RequireHttps` | HTTPS-редирект (по умолчанию `true`) |

Схема создаётся автоматически при первом запуске (или вручную из `deploy/postgres-schema.sql`). В продакшене поставьте сервер за обратный прокси (nginx/IIS) с TLS-сертификатом; заголовки `X-Forwarded-*` поддерживаются.

> **Важно:** при смене приватного ключа все выданные токены станут недействительны, а клиент нужно пересобрать с новым публичным ключом. Сохраните резервную копию `license-signing.pem`.

## Что проверено

* Сборка всего решения без предупреждений (WPF-клиент собирается и публикуется под `win-x64`).
* 17 автотестов: проведение закупок/продаж/возвратов, средняя себестоимость, атомарный откат при нехватке товара, запрет ухода кассы в минус, перемещения и инвентаризация, сверка регистров с журналами, отчёт о прибыли, подпись и подделка токенов, лимит устройств, блокировка, повторная выдача триала, доступ к панели.
* Сервер прогнан вручную на PostgreSQL 16: регистрация → выдача ключа в панели → продление → активация → блокировка → отказ при проверке.
